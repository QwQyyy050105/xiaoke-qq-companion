# 给不熟悉技术路线的使用者

先运行 README 的离线演示。演示成功后只选一种平台接入和一种模型路线。以下提示词可复制给帮助你的 AI 或开发者；尖括号内容由你替换。不要粘贴密钥、登录二维码、凭据或完整聊天记录。

## 选择路线

```text
我不熟悉部署，请先阅读 docs/CHOOSING_A_TEMPLATE.md。
我的系统：<例如 Windows 11>；平台：<个人微信 / 官方 QQ Bot / 已有 OneBot>。
已有条件：<平台应用权限 / 微信登录 / 网关；不要写密码>。
目标能力：<群聊、私聊、图片等>；模型来源：<API / Codex / DSH / 尚无>。
请解释适合的项目和缺少的条件，先带我跑离线演示，再配置真实接入。
每步说明成功时应看到什么，失败时先读取 doctor 输出。不要承诺未经测试的设备版本。
```

## 配置模型 API

```text
服务商官方文档：<链接>；base URL：<地址>；准确模型标识：<名称>。
API key 已存在本机环境变量：<变量名，不是值>。
请核对本项目请求格式、端点是否需要 /v1、超时和响应限制。
先用本地假服务器验证请求，再单独验证真实模型。
不要把 key 写入日志、导出配置或 Git，不要静默更换模型。
不支持工具、图片或流式时明确说明。
```

## 编辑独立人格

```text
请通过角色配置或面板编辑，不改变收信授权、密钥或插件路径。
角色名：<名称>；别名：<列表>；说话节奏：<短句 / 适量展开>。
喜欢：<具体事物>；不喜欢：<具体行为>；人物关系：<本机维护的关系结构>。
请求含糊时先问最关键的问题；区分原始消息、转述、事实和推断。
给三组前后对照，验证风格与上下文理解。不要靠提示词虚构联网或读图能力。
```

## 增加设备或能力

```text
系统/设备：<版本>；应用或网关：<准确版本>；功能：<能力>。
官方协议资料：<链接>。
先阅读 docs/EXTENDING.md（若存在）和 docs/PORTABILITY.md，使用当前版本接口。
先提交可运行的本地假服务和测试，再连接账号。
缺失能力明确 unsupported，不扫描其他账号或全盘，不套用未知版本偏移。
说明配置、版本范围、超时/取消和卸载方式。
```

## 排障

```text
项目/commit：<版本>；系统/Node：<版本>；接入路线：<路线>。
模型路线：<仅类型与模型名，无密钥>；故障时间和时区：<时间>。
最少复现步骤：<使用虚构消息>；预期/实际：<描述>。
doctor 输出：<先去除 token、真实会话 ID、人名和路径中的用户名>。
请按接收、触发、队列、模型、发送分阶段定位，不把进程启动当成收发正常。
```

## 发布自己的 fork

```text
请按 CONTRIBUTING.md 执行全部离线检查和 npm run check:release。
从新的空目录 npm ci，运行测试、demo --smoke 和 doctor --json。
只提交源码、示例、许可证和文档；不得提交账号配置、.env、状态、历史、个人媒体。
列出未做真实账号验收的部分，不能把预留接口写成已实现。
```
