# 设备、版本与扩展边界

核心、平台适配器和可选能力分别验收。离线核心可跨系统运行，不代表真实平台适配器跨系统可用。当前优先 Windows/电脑端，不声明手机常驻或未知桌面版本兼容。

## 选择安装体积

Windows PowerShell 若提示“无法加载 npm.ps1，因为在此系统上禁止运行脚本”，可以在同一目录使用 `npm.cmd`：例如 `npm.cmd ci --omit=optional`、`npm.cmd run demo -- --smoke`。它随 Windows 版 npm 提供，不需要为此修改全机执行策略。若系统连 `node --version` 或 `npm.cmd --version` 也找不到，先安装 README 要求的 Node 版本并重新打开终端。

标准安装 `npm ci` 包含全部 npm 可选组件。只需要文字聊天、API 模型和本地面板时，可在停止程序后选择精简安装：

```sh
npm ci --omit=optional
npm run demo -- --smoke
npm run doctor -- --json
```

这会省略公式排版、浏览器自动化、SILK 语音编码依赖。普通文字启动不会加载 KaTeX、Playwright 或 SILK。仅对应能力真正执行时才导入。精简模式不要启用这些能力；启用但未安装时会报缺少依赖，不会自动下载或假装成功。恢复完整依赖后，浏览器程序、语音服务、图片处理等外部运行环境仍需按功能说明配置。

恢复完整组件时，先停止程序，再运行 `npm ci --include=optional`，然后重新启动。两种安装使用同一份锁文件，不改模型、人格卡或会话授权。`npm ci` 会重建依赖目录；请勿在机器人仍运行时切换。可选包安装失败不一定使 npm 整体退出失败，使用对应能力前仍需检查实际安装结果。

完整开发与发布回归使用完整依赖；精简模式的演示、诊断和核心测试只证明相应子集，不能代替全部媒体或高级路线验收。大体积第三方运行环境可以省略安装，扩展接口仍保留。连接恢复、身份核验、取消、重复消息保护和发送回执不因精简模式被关闭。

## 扩展契约

从[本仓库的扩展契约](EXTENDING.md)和[示例插件](../examples/plugins/greeting.mjs)开始。三个模板都用 `apiVersion`、`id`、`capabilities` 和 `setup` 描述插件，但传入参数和返回值不同；跨模板迁移时需按目标仓库的示例适配。

只加载部署者本机明确配置的模块。插件是受信任代码，具有宿主权限；本模板不提供代码沙箱。聊天和模型输出不能加载代码或扩大权限。

新增平台或应用版本适配时，提供如下发布清单和测试：

```json
{
  "apiVersion": 1,
  "id": "example_transport",
  "platforms": ["win32"],
  "appVersions": ["the exact version tested"],
  "capabilities": ["receive.text", "send.text"]
}
```

这是一份适配器发布清单建议，不表示现有加载器自动执行全部字段。适配器自身必须验证版本和能力；未验证的版本返回 unsupported_version，不能套用偏移或伪造成功。

## 身份、消息与权限

平台 ID 使用字符串，避免整数精度损失。昵称、群名和备注不是稳定 ID。消息发送者与引用消息原作者分别处理；转述某人说话不能替换当前发送者。

在授权配置里添加平台提供的群 OpenID 或用户 OpenID，初始名单为空。使用同一人格不会合并不同会话的记忆。

## 模型与媒体

兼容 API 明确 endpoint、认证、model、超时、取消、输出上限和错误类型。先用本地假服务验证 URL、请求体及错误处理，再验真实服务。文本成功不能推断工具、图片或流式可用。不可用时明确报告，不静默更换提供商。

语音需分别确认平台音频、编码与 ASR；图片需确认授权会话归属、字节获取与模型格式支持。搜索需显式检索能力，普通模型 API 不等于浏览器。

## 迁移小柯到另一台电脑

先决定新机器运行的是同一个 QQ 官方机器人，还是一个新申请的应用。新应用可以沿用说话风格，群和用户的 OpenID、主人绑定与历史应从新应用重新建立。同一应用换主机时，在旧终端按 Ctrl+C 并等进程退出，再备份和切换，避免两台机器同时消费事件。

| 旧目录中的内容 | 什么时候带到新机器 |
| --- | --- |
| `character_card.local.json` | 想保留面板编辑过的人格时复制；没有这个文件会读取随源码发布的 `character_card.json`。另在面板的配置页核对叫名别名、语气和静默时段。 |
| `config.local.json` | 同一应用继续运行时复制，包含模型配置、允许的会话和配对哈希。新应用先初始化，再在面板填写自己的值。 |
| `.env` 或服务的环境变量 | 在新机器的私有目录或服务环境重新配置 QQ 凭据、配对口令和选用的模型密钥。环境变量优先于同名的 `.env` 项。 |
| `data/` | 同一应用需要恢复主人绑定、历史、记忆、收藏与面板聊天设置时，在旧服务退出后整体私下备份。新应用使用新建的数据目录。 |
| 自编插件、自备素材与可选运行环境 | 在新机器安装并核对插件的项目相对路径、素材目录，以及 `CODEX_CLI_PATH`、`XIAOKE_PYTHON_PATH` 等本机路径。自建 Python 虚拟环境按新系统重建。 |
| `node_modules/`、`temp/`、缓存 | 在新系统按锁文件重新安装依赖，让程序重新创建临时目录和实例锁。 |

1. 在新机器的可写目录取同一版本源码。先运行 `npm ci` 和 `npm run demo -- --smoke`，应看到 `DEMO_SMOKE_OK`。此时还不需要复制账号文件。跨系统或更新版本时，先完成同版本恢复，再单独升级。
2. 程序停止时恢复选定的文件。在新目录运行 `npm run init`，它会补齐缺少的本地配置和 `.env` 模板。填好凭据后再运行一次，用当前配对口令生成哈希。打开 `npm run demo` 核对角色与会话配置，完成后按 Ctrl+C。
3. 运行 `npm run doctor -- --json`。确认必需项就绪，旧服务已停止，再用 `npm start` 启动新服务。用一个已授权会话验收。若需要回到旧机，先正常退出新服务，再打开旧部署；切回后新机产生的历史不会自动合并。

定时任务或快捷方式可以从其他工作目录调用 npm。以下是 PowerShell 示例，把引号中的值替换成实际克隆目录。macOS/Linux 终端可直接运行 `npm --prefix "/path/to/your clone" run doctor -- --json`。项目路径包含空格或中文时保留引号。

```powershell
$project = 'E:\Bots\我的小柯'
npm.cmd --prefix "$project" run doctor -- --json
npm.cmd --prefix "$project" run demo -- --smoke
```

## 顺着一条测试消息排查

| 在哪里停住了 | 下一步 |
| --- | --- |
| 无账号，`doctor` 返回 `needs_setup` | 看 `checks` 中的 `id` 和 `ok`。只想演示可以直接跑 `demo -- --smoke`。诊断正常退出只说明检查执行完毕。 |
| `model` 待配置 | API 路线核对模型名、base URL 和密钥环境变量名。本机 Codex 路线检查可执行文件是否在 PATH，或将绝对路径写入 `CODEX_CLI_PATH`。离线诊断仅核对配置；有意验证真实模型时，用 `npm run chat` 发送一条测试句，输入 `/quit` 退出。 |
| 面板能试聊，QQ 收不到消息 | `demo`、`panel`、`chat` 都不接收 QQ 事件。结束独立面板后启动 `npm start`，看运行面板中的连接状态。遇到 QQ 凭据错误码 100016 时，在本机核对 AppID 与 AppSecret 是否属于同一官方应用，更改后重启。 |
| 电脑刚开机或正在换网络，首次连接失败 | 保持 `npm start` 运行。DNS、网络超时、取令牌时的 HTTP 429 或服务端 5xx 都会进入重连，首次等待 2 秒，后续间隔逐步增加，最长 60 秒。网关确认会话后，面板更新为已连接，并依配置恢复主动聊天。等网络恢复后发一条新消息核对。按 Ctrl+C 可以结束等待。 |
| 已连接，指定群或私聊仍没有回复 | 用获准测试的群或用户，核对开放平台事件权限、配置中的 OpenID、参与模式和静默时间。默认群聊模式可用一次明确的 @ 提及验证。主人配对在已授权的私聊完成。 |

在面板查看运行记录，按接收、触发、队列耗时和 QQ 发送回执定位。重新部署后查看当前进程的记录时间，最后以自己在 QQ 中实际收到的内容验收。
